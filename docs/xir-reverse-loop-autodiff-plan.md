# XIR Autodiff: Reverse-Mode Loops Plan

## Status

**Design stage.** The bounded-unroll strategy for dynamic loops inside
autodiff scopes is the dominant cost of large training kernels: a two-level
loop with hidden size H emits up to `budget²` cloned loop bodies (64² = 4096
for the MLP regression kernel), which Metal then spends 10+ minutes compiling.
This document plans replacing the clone-everything strategy with true
reverse-mode traversal over loops.

## Problem

### Current behavior (`src/xir/passes/autodiff.cpp`)

1. `analyze_simple_counted_loop` proves a fixed trip count only for
   canonical `for (i = c; i < const; i++)` loops with a **compile-time
   constant** bound.
2. Loops whose bound is a runtime value (e.g. a `Uniform<int>` push
   constant, as in Feather's NN training kernels) fall to
   `unroll_bounded_dynamic_loop`: the loop body is **cloned up to
   `max_ad_loop_unroll_count` (64) times**, each clone gated at runtime by
   the loop condition, plus an `unreachable` overflow trap.
3. Nested dynamic loops multiply: an MLP layer (`for j … for k …`) emits
   up to **64 × 64 = 4096 cloned bodies**. Feather's 3→12→12→1 regression
   kernel grows from 3,102 instructions to ~247k (GVN/DCE trims to ~200k),
   and Metal compiles that shader for 10–15 minutes per process (the Metal
   backend has no persistent pipeline cache).

### Why GVN/DCE cannot rescue it

The clones share no subexpressions: every clone loads its own intermediates
from scratch buffers (layer-to-layer activations), and GVN is conservative
around memory. Observed trimming is only ~19%.

### Attempted mitigations (all insufficient)

- GVN/DCE/simplify after autodiff (Feather `618b487`): −19%.
- float4 vectorization of inner products: expansion unchanged (each vector
  op expands to per-element adjoints; clone count dominates).
- Lowering `max_ad_loop_unroll_count` 64→32: only ~1.4× faster compile
  (Metal shader compilation is super-linear in instruction count) and it
  turns hidden sizes > 32 into runtime crashes — rejected.

## Goal

Support reverse-mode autodiff over loops **without unrolling**: the adjoint
of a loop is a reverse loop that replays the forward iteration in reverse,
accumulating parameter gradients. Code size then scales with the loop body,
not the trip count — a 12×12 MLP layer costs one body clone instead of 4096.

## Design sketch

### 1. Forward trace storage

Reverse traversal needs the forward values of each iteration. Two strategies:

- **Checkpointing (default)**: recompute forward values in the reverse loop
  instead of storing them; store only loop-carried dependencies (induction
  variable history, or a single checkpoint per iteration when recomputation
  is too expensive).
- **Value stack**: store per-iteration intermediates in an alloca-backed
  array of compile-time-unknown length — XIR has no dynamic arrays for
  locals today; requires either a scratch buffer (bounded by trip budget,
  falls back to checkpointing) or growable memory (out of scope).

Recommendation: start with **recompute-based reverse loop** (correct,
memory-free, no new IR), with per-iteration checkpointing of the induction
variable only. Optimize to value stacks later.

### 2. Loop shape requirements

The reverse pass must match the forward trip count exactly:

- Only loops with a **provably side-effect-free prepare block** (the loop
  condition depends only on the induction variable and loop-invariant
  values) can be reversed.
- The loop body must not contain `break`/`continue` with side effects that
  change the trip count (early exits are fine if the exit condition is also
  reversed identically).
- Nested loops reverse inside-out (innermost adjoint first), which is the
  natural order for the existing structured traversal.

### 3. IR shape

Forward:

```
%i = 0
loop {
  cond = %i < %n
  br cond, body, merge
body:
  … forward ops (values cached or recomputable) …
  %i' = %i + 1
  br loop
merge:
}
```

Reverse (adjoint of the loop):

```
%i = trip_count         ; derived from the forward loop's induction
reverse_loop {
  cond = %i > 0
  br cond, rbody, rmerge
rbody:
  %i = %i - 1
  … adjoint of forward body with forward values recomputed/cached …
  br reverse_loop
rmerge:
}
```

The adjoint of the body is generated by the existing per-instruction
adjoint machinery; the new piece is the reverse-loop scaffolding plus the
forward-value recovery per iteration.

### 4. Integration points (`src/xir/passes/autodiff.cpp`)

- `unroll_fixed_trip_loops` / `unroll_bounded_dynamic_loop`: add a third
  path, `reverse_loop_adjoint`, selected when the loop is reverseable
  (prepare purity + no dynamic early exits).
- `TransformAdScope`'s value-caching: when a loop is reversed, cache
  forward values either in a per-iteration scratch buffer (bounded) or
  recompute; do not keep the unrolled clones.
- `max_ad_loop_unroll_count`: keep as the fallback for non-reverseable
  loops; optionally raise it once cloning is rare.

### 5. Validation

- Unit tests: `src/tests/unit/xir/` — reverse loop with constant and
  runtime trip counts; nested loops; early-exit loops; side-effect-free
  prepare requirement enforcement.
- End-to-end: Feather `AdMlpRegression` (3→12→12→1) must compile in
  seconds (not 10+ minutes) with identical training convergence;
  `Feather.AD.Tests` (66) and `Feather.NN.Tests` (78) stay green.
- `AdGptDemo` becomes feasible again (currently hours of Metal compile).

## Risks

- **Forward-value recovery**: recomputation must be exactly equivalent
  (floating-point reassociation could diverge); caching needs bounded
  scratch per iteration.
- **Loop-carried gradients**: a parameter written inside the loop body
  accumulates gradients across iterations; the reverse loop must initialize
  the gradient slot once before the reverse loop, not per iteration.
- **Early exits**: `break`/`continue` with side effects cannot be reversed
  without storing the exit trip count; reject them initially.

## Non-goals

- Dynamic memory / growable value stacks (first milestone uses
  recompute-based reversal).
- Autodiff over `SimpleLoopInst` (already rejected today).
- Parallelism across reverse iterations (sequential reverse is required by
  data dependencies).
